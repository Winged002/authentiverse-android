# Digital Space Android 1.1.4 fixes

- Accept the control plane's explicit isolated-Indoor `0.0.0.0/0` policy while
  continuing to reject unknown and out-of-Area route combinations.
- Capture IPv6 in isolated mode to prevent public Internet leakage.
- Require private Area DNS for isolated mode and wait briefly for Android to
  install the VPN DNS route before registering the Indoor inbox.

- Present the issued device certificate to `internal.syntal.pro` for Area,
  membership, profile-certificate, and tunnel operations.
- Continue using Android's public trust store for the public control plane.
- Present the enrolled device certificate to the private control-plane API at
  `api.digitalspace.home.arpa`, matching its device-CA Nginx listener.
- Retain the short-lived Area profile certificate for profile-authorized Area
  applications such as `home.digitalspace.home.arpa`.
- Validate the Indoor server with the pinned Digital Space server CA.
- Migrate an existing 1.1.1 enrollment by retrieving and persisting the missing
  Indoor server CA; a new invitation is not required.
- Parse the control plane's `area_name` response field.
- Use the precompiled official WireGuard Android tunnel dependency on Windows.
- Include `gradlew.bat` and fix primitive `ByteArray` DER conversion compilation.

After installing the updated debug build over the existing debug application,
open Digital Space and press **Refresh Areas**. The existing device identity,
session token, certificates, and WireGuard key remain in Android app storage.
